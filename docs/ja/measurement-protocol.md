# 測定プロトコル

ユニットを測定する順序です。各段階は前の段階が書いたファイルによって狙いを定めるため、順序は便宜ではなく手法の一部です。順序を外して実行した段階は、このアーカイブが記述できないものを測ることになります。

2 台のユニットを比較する主張は、どちらもこの方法で測定されていることに乗っています。異なる方法で測定したユニットも単体としては記述できますが、比較には参加できません。

## どの段階よりも前に

すべてのコマンドは、何かを書き込む前に MIDI 経路を検証します。自己診断は単独で先に実行してください。そうすることで、失敗が「たまたま実行していた段階の失敗」ではなく「経路の失敗」として読めます。

```sh
rye run soundings selftest --audio "<audio interface>"
```

自己診断の合格が示すのは、ハーネスがユニットを読めることだけです。そのユニットを探索して安全であることは示しません。すべての段階に共通して 2 つの制約があります。

- **一括要求は 64 バイト以下に保つ**。これを超える要求は、ユニットの応答を完全に停止させることが実測されています。復帰には電源の再投入が必要です。
- **応答することが分かっているアドレスを定期的に問う**。応答しなくなったユニットは、存在しないアドレスの空間として読めます。沈黙を不在として扱う探索は、何も測らないまま正常終了します。

## 段階

### 1. 識別

```sh
rye run soundings identity
```

Identity Request に対してユニットが返すものを記録します。返答は背面の定格表示、測定チェーン、ユニットの設定とともに `meta.json` へ verbatim で入ります。以降に測定するものはすべて、この記録にスコープされます。

### 2. 電源投入時の状態

ユニットへ何かを書き込む前に、RQ1 だけを送って空間を 2 度読み取って取得します。得られるのはユニットが電源投入時に置かれている状態であり、いずれかの段階が書き込んだ後は、次の電源再投入まで取得できません。

2 回の読みが食い違ったアドレスは、解決せずに一覧として残します。以降のリセット測定はすべて、このファイルと比較されます。

### 3. アドレスマップ

```sh
rye run soundings sweep --out data/units/<unit-id>/address-map.json
```

どのアドレスが応答するかをユニットに問います。このマップは文書が列挙するものではなくユニットが答えたものであり、以降の段階はこれを狙って実行されます。マップに無い領域は、以降に測定されるすべてから外れます。

### 4. 窓

```sh
rye run soundings window-probe --stores <addr> <addr> <candidate>...
```

自分の値を保持しているブロックと、別のブロックの値を見せているブロックとを判別します。アドレスが何を保持しているかを解釈する段階より前に実行します。窓は、書き込んで読み戻す方法では格納と区別できないためです。書き込みが窓を向け、読みがそれに追従するので、そのアドレスは与えられたとおりの値を答えます。

窓と判定されたブロックは、それを記述する記録の中で名指しされ、以降の段階では除外されます。除外しなければ、同じストアを、その素性を残さない名前で何度も測ることになります。

### 5. 受理される値

```sh
rye run soundings write-probe --map data/units/<unit-id>/address-map.json \
  --resume --out data/units/<unit-id>/write-probe-wholemap.json
```

各バイトを単独で書いて読み戻し、そのアドレスが何を受理し、何をクランプし、何を拒否するかを記録して、元に戻します。領域は終わった順に書き出されるため、中断した実行は最後に完了した領域から再開できます。

1 バイト読みに応答しないアドレスへは書き込みません。戻すものが存在しないためです。それらは skipped として記録します。そのうちどれが未定義で、どれが「より大きなブロックとしてのみ到達できる」ものなのかは、この段階では決着しません。

### 6. 独立した格納

```sh
rye run soundings hold-probe --map data/units/<unit-id>/address-map.json \
  --out data/units/<unit-id>/hold-probe-wholemap.json
```

隣接するアドレスへ異なる値を与えてから、どれも読まずに全部を読み戻します。これにより、1 つのセルに支えられた連続アドレスと、それぞれが別のセルである連続アドレスとを分離できます。順序そのものが手法です。書きと読みを分ければ、近傍へ最後に書かれた値しか見せないアドレスはその 1 つの値を答え、隣接アドレスはそれぞれ自分の値を答えます。

この段階は、別のブロックをミラーしているブロックを見つけません。それは段階 4 が問うことです。

### 7. エイリアス

```sh
rye run soundings alias-scan --map data/units/<unit-id>/address-map.json \
  --prefix "" --kind cc --out data/units/<unit-id>/cc-aliases-ch1.json
```

ある系統のメッセージを 1 つずつ送り、その前後でアドレス空間を差分して、メッセージが到達する格納場所を特定します。系統ごとに 1 回ずつ実行します。`cc`、`nrpn`、`rpn`、`channel`、`drum-nrpn`、および SysEx による書き込みの `address` です。

**マップ全域を監視してください**。1 つのブロックに限定した走査は、そこで得られる否定的所見のすべてをそのブロックへ限定します。「このメッセージはどこにも格納されない」という記録は、そのとき「監視した空間の 1 割のどこにも」という意味になります。

### 8. リセット

```sh
rye run soundings reset-probe --baseline data/units/<unit-id>/power-on-state.json \
  --map data/units/<unit-id>/address-map.json \
  --write-probe data/units/<unit-id>/write-probe-wholemap.json \
  --out data/units/<unit-id>/reset-probe.json
```

各リセットの前に状態を壊し、後で空間を読みます。これにより、文書がリセットについて述べていることではなく、そのリセットが実際に復元するものを測定します。マークを置くのは、書き込み探索が「任意の値を受理する」と判定したアドレスに限ります。クランプするアドレスは元の値を保ったままかもしれず、壊されなかったバイトはリセットについて何も語らないためです。

すべてのリセットは同一のリセットを前置して実行します。そうすることで、結果を互いに比較できます。前置しなければ、各結果は「直前のリセットがたまたま残した状態」を基準に読むことになります。

### 9. 音色とエフェクト

```sh
rye run soundings tone-map --out data/units/<unit-id>/tone-map-m0.json
rye run soundings efx-map --out data/units/<unit-id>/efx-type-map.json
```

各音色と各挿入エフェクトを要求し、受理されたかどうかを読み戻します。走査前に標本抽出を行うマップは、その標本抽出を但し書きとして持ちます。`--exhaustive` は全バンクに 128 プログラムすべてを問うもので、但し書きの付かない唯一の形式です。

### 10. 再現性 — あらゆる音の比較より前に

```sh
rye run soundings repeat --audio "<audio interface>" \
  --out data/units/<unit-id>/repeatability-p0.json
```

同一の刺激を 2 回鳴らし、2 つのテイクがどれだけ一致するかを測定します。この数値が、以降のあらゆる差分測定の床になります。床を下回る領域では、「差が無い」と「差を見る解像度が無い」は同じ読みです。

床はユニットと測定チェーンの両方の性質なので、ユニットごとに測定し、チェーンを変更したときは測定し直します。

### 11. 可聴な差

```sh
rye run soundings contrast --cc 91 --audio "<audio interface>" \
  --out data/units/<unit-id>/audible-cc91.json
```

1 つのパラメータの 2 つの設定を、再現性の床を基準に比較します。これにより、ユニットが格納するパラメータと、それを通して実際に聞こえるパラメータとを分離できます。格納されていて可聴でないパラメータは存在します。アドレス空間側の段階はその区別をつけられず、この段階はつけられます。

`transfer`、`motion`、`decay` はそれぞれ、アナログ経路、時間変化するエフェクト、エフェクトの減衰を測定します。`motion` と `decay` はテイクを読むだけで、ユニットの接続を必要としません。

## すべての記録が持つもの

何も見つけなかった段階は、その実行が何かを見つけられたはずである場合にのみ読む価値を持ちます。そのため各記録は、その実行が備えていたコントロールを明示します。

- **陽性対照**。最初の刺激の前と最後の刺激の後に送ります。1 回だけ送られた対照は、その実行の残りについて何も語りません。
- **試験対象の系統が実際に到着したかどうか**。陽性対照はコントロールチェンジであり、他の系統のメッセージが通ったことは示せません。これを欠く実行では、すべての否定的所見はユニットではなく経路についてのものになります。
- **書き込んだブロックの外への着弾を報告できたかどうか**。あるアドレスへ書いてそのアドレスしか動かなかったという実行は、そこをミラーするものが無い証拠になりますが、それは他所へ着弾していたら報告されたはずである場合に限ります。
- **何を復元したか、そして何を対象から外したか**。実行が覆うのをやめた範囲は、その実行が述べることすべてに掛かる但し書きです。

## 測定チェーン

チェーンはプロトコルの一部です。インタフェース、ゲイン、結線、収録方法はユニット間で同一に保ちます。そうしなければ、2 台のユニット間のレベル比較を、2 つのチェーン間の差と区別できません。

やむを得ずチェーンを変更した場合は、その差異を `meta.json` の `measurement_chain` に記録し、そのユニットを含むレベル比較には「確立していない」と付記します。

実機を使う段階は直列です。オーディオインタフェースが 1 つ、ユニットが 1 台という条件では、前景の収録中に背景の実行が鳴り、再現性が静かに崩壊した数値だけが残ります。

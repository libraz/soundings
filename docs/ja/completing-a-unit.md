# ユニットを完了する

1 台分のディレクトリが終わったと言えるために、何が成り立っている必要があるかを記述します。プロトコルが段階を記述するのに対し、ここでは実行すべき段階がもう無いのはいつかを記述します。

ユニットが完了するのは、**すべての段階について説明がついているとき**です。実行して記録が下の基準を満たしているか、あるいはその段階が当てはまらない理由が `meta.json` に書かれているか、そのどちらかです。完了は機体ごとに宣言します。他の機体を待つものは何もなく、完了したディレクトリはそれ単独で使えます。

この区別が要るのは、ある段階が想定していた系統の外にある機体は、その段階に返す答えを持たないからです。「まだ実行していない」と「当てはまらない」は、ディレクトリを見ただけでは同じに見えて、読む人にとっては逆の意味になります。

## 段階ごとの基準

| 段階 | 完了の条件 |
|---|---|
| 識別 | `meta.json` が identity reply、背面の定格表示の verbatim、測定チェーン、セレクタのポジション、ファームウェアについての記述を持つこと。ユニットが使える情報を報告しない場合は「未解決である」と書かれていること。 |
| アドレスマップ | 掃引がトップバイトの全範囲を覆い、自身を trustworthy かつ complete と報告していること。 |
| 電源投入時の状態 | 書き込みを行う段階より前に取得され、食い違い一覧と未読領域数が記録されていること。 |
| 窓 | アドレスマップ上で他のブロックと同一に応答するブロックすべてに、複数のオフセットで測定された窓の判定があること。未検証のブロックは、以降のすべての記録が別の場所についてのものかもしれないブロックです。 |
| 受理される値 | 書き込み探索がマップの全領域を覆い、全領域が復元され、飛ばしたバイトが一覧されていること。 |
| 独立した格納 | hold probe がマップの全領域を覆っていること。 |
| エイリアス | ユニットが応答する系統ごとに 1 回ずつ、いずれもマップ全域を監視し、いずれもコントロールを備えていること。走査しなかったパートが記録に名指しされていること。 |
| リセット | ユニットが受理するすべてのリセットについて、全域の書き込み探索を元にマークを打ち、電源投入時の状態と比較されていること。 |
| 音色とエフェクト | ユニットが受理するすべてのマップセレクトについての音色マップ（最初の 1 つだけではなく）と、全タイプを問うたエフェクトタイプマップ。 |
| 再現性 | このユニットをこのチェーンで測った床が存在し、チェーンを変更したら測り直されていること。 |
| 可聴な差 | メッセージで到達できるパラメータすべてに可聴判定があるか、明示された除外に該当すること。 |
| ブロック全体 | 種類ごとに 1 ブロックを完全に掃引し、そのプランに対して数え合わせてあること。未質問がゼロで、どの値の組も作れないアドレスが名指しされていること。1 つのブロックに現れて同種の他ブロックに現れなかった判定は、公開前に問い直されていること。 |
| エフェクト応答 | まず経路を確立すること。ユニットのアナログ入力に与えた信号がそのエフェクトに届くかを、立てた状態が実際に何かをすることを示す対照つきで測定します。届かない場合、既知の信号をエフェクトに通して掃引する手法はそのユニットでは使えず、この段階はユニット自身の発音で支えられる範囲になります。その上で、エフェクトのパラメータすべてが可聴判定を持つこと。判定はエフェクトのタイプ単位ではなく、パラメータ単位で取ります。同定作業が必要とする曲線（下記）は、完了の条件には含めません。 |

## 可聴判定が、高価な測定の入口を制御します

エフェクトのパラメータを全範囲にわたって振り、設定ごとに応答を収録する作業は、この中で最も高価で、しかも自然な終わりがありません。これを制限するものが 2 つあります。

**門はパラメータ単位で問います。** 門の価値は、それが何を退けたかで決まります。エフェクトのタイプ単位で問う門は、そのユニットが持つタイプを 1 つも落とさないことがあり、その場合、掃引すべきパラメータの数は最初のまま残ります。したがって掃引を許可する可聴判定は、パラメータについて取ったものとします。全タイプの全パラメータをスクリーニングする作業はそれ自体が 1 つの段階であり、着手前にコストを算出できます — パラメータ数に、安い比較 1 回分のコストを掛けたものです。

ユニットが格納していても、それを通して聞こえないパラメータには応答測定を行いません。「格納されていて、かつ可聴でない」ということ自体が所見です。

**掃引は要求されて行うものであって、あらかじめ予定するものではありません。** スクリーニングには終わりがあり、掃引にはありません。ユニットが完了するのは、そこで何が可聴かが地図になったとき — 各々の否定的判定を読めるものにする境界と対照を伴って — です。曲線はその後、名指しされた下流の問いがそのパラメータを必要としたときに、1 つずつ描きます。何が scope に入るかを決めるのと同じ規則です。完了したユニットとは、それらの問いを差し向けられる状態のユニットであって、既に答え終えたユニットではありません。

曲線を要求されたパラメータについての基準は、アルゴリズムを同定できる素材であることであって、その要約ではありません。

- 逆畳み込みされた応答を、それを生成した刺激と並べて数値として保持すること
- 高調波の各次数が線形応答と分離されていること。畳み込まれたままにしないこと
- パラメータ自身の設定値を範囲にわたって標本化し、7 ビット値から物理量への写像 — 遅延のミリ秒、オクターブ帯域ごとの減衰、変調のレート — が両端 2 点ではなく実測された曲線であること
- その曲線に現れる量子化が見えていること。段差は機械についての事実であり、そこを補間したものは事実ではありません

## 完了に必要でないもの

- **すべてのバイトの説明**。応答し、ある範囲を受理し、どのメッセージも到達しないアドレスは、完全に測定されています。それが何のためにあるかは、このアーカイブの問いではありません。
- **すべてのパートやチャンネルの走査**。種類ごとに 1 つずつ走査し、残りを名指ししてあれば完了です。16 個すべてを走査しても、より完了するのではなく、より高価になるだけです。
- **可聴なパラメータすべての掃引**。成果物は何が可聴かの地図であり、曲線はそこから要求に応じて描きます。終わる前にすべての問いに答えなければならないユニットは、決して終わりません。そして問いはまだ出そろっていません。
- **何らかのモデル**。アルゴリズムを名指しせず、topology を当てはめず、係数を推定しません。ユニットが完了するのは、そこから導出できる状態になったときであって、導出し終えたときではありません。
- **他のユニットとの一致**。他の個体と異なる結果は、それ自体が結果です。

## 当てはまらない段階

`meta.json` の `stages_that_do_not_apply` に記録します。キーは上表の段階名、値はその理由です。段階を飛ばすのは、ユニットがそれに答える手段を持たないからです。手間がかかるから、あるいは答えが面白くなさそうだから、ではありません。

## ユニットが今どこにいるかを問う

`soundings complete <ユニットのディレクトリ>` が、ディレクトリを上表に対して数え、残りを表示します。判定は構造的なもの — ファイルが在る、フラグが立っている、ある数が別の数と一致する — に限られるので、ここで「met」と出た段階は、読まれたのではなく数えられただけです。対照が十分だったか、否定的判定が境界を伴っていたかのように、読む人にしか決められないものについては、通過させずに「判定できない」と出します。

残りはアドレス数・パラメータ数として出し、時間では出しません。レートはチェーンと刺激に属するものであり、あるユニットで測ったレートは次のユニットについての事実ではありません。どれが当てはまるかを知っているのは実施者です。

[![Platform](https://img.shields.io/badge/platform-macOS%20%7C%20Linux%20%7C%20Windows-lightgrey)](https://github.com/libraz/soundings)

`soundings` は、ハードウェア MIDI 音源の MIDI 制御面と音響上の振る舞いを測定します。Python 製のコマンドライン・ハーネスと、個体ごとの測定結果を収録したバージョン管理済みのアーカイブで構成されています。

仕様書の転記ではなく、実機で観測した振る舞いを記録します。対象は、読み出せるアドレス、受け付ける値、リセット後・電源投入後の状態、メッセージの別名、利用可能な音色とエフェクト、音響測定です。結果は特定の個体と測定環境に限定されます。

アーカイブは **[soundings.libraz.net](https://soundings.libraz.net)** で公開しています。アドレス検索、2 つの縮尺で 1 つのグリッドとして描いたアドレス空間、音色とインサーションエフェクトのカタログ、公表文書の記載を対応する測定の隣に並べた表示、そして測定結果だけで動くブラウザ上の操作面エミュレータがあります。サイトを組み立てるのは [`soundings-homepage`](https://github.com/libraz/soundings-homepage) で、その同期ステップがこのリポジトリのチェックアウトを読み、サイトが配信する形へ変換します。こちらの記録が裏付けないことはサイト側で一切主張せず、測定されていないものはゼロや空欄ではなく *未測定* として描きます。

## 対象範囲と現状

現在のアーカイブには、Roland SC-8850 1 台の測定結果が `data/units/roland-sc8850-01/` に含まれます。アドレスマップと各領域の境界、各ブロックがどのオフセットで応答するか、各アドレスが受け付ける値と自分の値を保持するかどうか、電源投入直後の状態、各リセットが復元するもの、メッセージ族ごとの保存先、音色とインサーションエフェクトのカタログ、そして音響測定 — 繰り返しの安定性、単一アドレスでの可聴差とそれをブロック単位に集約したもの、インサーションエフェクト個別の型のパラメータ、エフェクトの減衰と変調、そして設定値ごとの量を追った掃引 — レートのスロットが何 Hz で変調したか、パラメータが 1/3 オクターブ各帯域のレベルに与えた影響、ディレイのスロットが返すコピーをどこに置いたか、パラメータが 2 チャンネル間のバランスに与えた影響です。

アドレス空間は繰り返し構造を持つため、網羅率はアドレス数ではなく形状に対する分数で数えます。応答したオフセットの集合が一致する 2 つのブロックは同じ形状です。各形状について代表を 1 つ完全に測り、まとめられるかどうかは仮定せず、同じ形状の別のブロックをもう 1 つ読み出して一致を記録します。`soundings complete <個体ディレクトリ>` は、個体を完成の基準に対して数え、何が残っているかを述べます。

測定結果は、同じ型番やファームウェアのすべての個体に当てはまることを示すものではありません。`meta.json` には個体の識別情報、個体から取得できたファームウェア情報、MIDI と音声の測定経路を記録しています。

アーカイブとは別に、そして意図的に `data/` の外に、`documents/` が公表された文書から読み取った事実の表を保持します。現時点では SC-8850 と SC-88Pro のオーナーズマニュアルで、メーカーの記載を実測と突き合わせられるようにするためのものです。ここにあるものは個体についての証拠ではありません。あるアドレスが `00 – 01` を受け付けると書かれた行は、ページにそう書かれていたことの証拠です。

## 測定から読み取ったもの

`data/` の記録は、機体が何を返したかを述べます。アルゴリズムの名前を挙げることも、構成を当てはめることも、係数を見積もることも、実装を描くこともしません。読み取り — その応答がどんな構造の反応なのか、あるバイトがどの表を引いているのか、当時の技術水準から何が有力なのか、このプロジェクトの外で誰が何を報告しているのか — は `inferences/` にあり、導出はこのディレクトリの中だけで行います。参照は一方向です。推論は記録を引用しますが、記録は推論を引用しません。このディレクトリを削除してもアーカイブは変わりません。

1 つの解釈を抱えたアーカイブは、その中の測定結果そのものより価値が低くなります。後から読む人が全員、使い始める前にまず何を差し引くべきかを考えなければならないからです。どちらに入れるか迷う文の判定基準は、こちらの読み取りに同意しない読者でもそれを使えるかどうかです。検証ではなく信用を要求する文は `inferences/` に属します。

主張が閉じる条件は 4 つのゲートです。残差の大きさは、棄却の下限としての役割を除けばそこに入りません。ゲートは、そのエフェクト自身が動かす幅に対する残差、機体自身の読み取りが持つ性質、`candidates/` の中で最も強い対抗候補が勝者とは違う方向へ傾くこと、そしてモデルが破綻する設定値が存在しないことです。棄却の下限とノイズフロアの間では、残差は報告するだけで最適化しません。それを下げていく作業は部屋と変換器を追いかけることだからです。`not-chased.json` は、モデルに説明を求めていないものを、それぞれ何の測定で範囲を押さえたかとともに列挙しています。

どちらも再現し、ここでの測定では区別できない 2 つの読み取りは、未解決として残すのではなく等価として記録します。先入観やコミュニティの報告だけに立つ主張は `standing_untested` とし、それを反証しえた測定の名前を挙げます。次に何を測るべきかは保持せず導出します。待ち行列は、現に立っている読み取りを主張から切り分ける観測量と、この測定系がそこで分解できる量に対する余裕で構成されます。何をもってしても切り分けられない対抗案は、その理由を述べたうえで未解決のまま残ります。

```sh
rye run soundings inferences closed   # 測定で決着しうる対抗案が残っていない主張
rye run soundings inferences open     # まだ立っている読み取りと、それを切り分けるもの
rye run soundings inferences stale    # 根拠にした数値が動いた主張
```

SC-8850 について現時点で読み取ったのは、インサーションエフェクトのパラメータマップです。型ごとではなくクラスごとに読んでいます。変調レート・ディレイタイム・フィルタ周波数のバイトはマニュアルが印刷している表の添字であること、エフェクトレベルのバイトは量子化幅を測定済みの 7 ビット乗数を格納した表であること、音色ゲインのバイトは 1 ステップ 1 デシベルであること、出力パンとエフェクトバランスのバイトは 2 本のランプの組であること、そしてあるイコライザ型が 4 段のフィルタと出力ゲインの連鎖であることです。

## インストール

必要なもの:

- Python 3.11 以上（[Rye](https://rye.astral.sh/) で管理）
- MIDI 測定用の双方向 MIDI インターフェース
- 対象となる音源。音響測定にはオーディオインターフェースも必要です

```sh
rye sync
rye run soundings devices
```

利用可能なコマンドは次で確認できます。

```sh
rye run soundings --help
```

## 実機を測定する前に

データを取る前に selftest を実行してください。

```sh
rye run soundings selftest --audio "<オーディオインターフェース>"
```

返信 SysEx のチェックサム、既知のアドレスに対する繰り返し読み出し、音声キャプチャの時間軸を検証します。ただし、この検証は未知の機器に対して安全にプローブできることを保証しません。実機に対してコマンドを実行する前に、ヘルプと既存の測定結果を確認してください。要求によっては応答が返らない、または電源を入れ直すまで機器が応答しなくなることがあります。

MIDI インターフェースの選択には `--port`、SysEx デバイス ID の指定には `--device-id`、3 バイトのアドレスをどの Roland モデル ID のもとで読むかの指定には `--model-id` を使います。複数のモデル ID で応答する個体は、そのそれぞれに別のアドレス空間を開きます。GS 以外の値を受け付けるのは、特定の族に依存しない段階だけです。3 つともグローバルオプションなので、サブコマンドより前に置きます。結果データを書き出すコマンドは、必要に応じて `--out` を受け取ります。

## コマンド

| コマンド | 用途 |
|---|---|
| `devices` / `selftest` | MIDI とオーディオのデバイスを一覧し、測定経路を検証します。 |
| `identity` / `read "40 01 30" 16` | Identity Request を送信し、Roland RQ1 でアドレスを読み出します。 |
| `sweep` / `boundary` / `offsets` | アドレス空間を地図化し、領域が地図どおりの位置で終わるかを確かめ、1 バイト読みでしか届かないアドレスを探します。 |
| `watch-set` | 後段が監視するアドレスを、その個体がすでに答えたものから組み立てます。sweep が定めるのはどのブロックが存在するかであって、どのアドレスが存在するかではないためです。 |
| `write-probe` / `hold-probe` / `window-probe` | アドレスが受け付ける値、自分の値を保持するかどうか、他のアドレスの値を映しているかどうかを測定します。 |
| `power-on` / `reset-probe` | 電源投入直後の状態を取得し、各リセットが復元するものを測定します。 |
| `tone-map` / `efx-map` | 利用可能な音色またはインサーションエフェクトを調べます。 |
| `alias-scan` | MIDI メッセージで変化する保存先を特定します。 |
| `port-send` / `port-read` | 応答を返さない MIDI 入力へ送り、それが機体に残したものを読み出します。 |
| `repeat` / `contrast` / `verdict` | 繰り返しの安定性と可聴差を測定し、以前に録ったテイクを判定します。 |
| `transfer` / `motion` / `decay` / `phase` / `vibrato` | 音声経路、時間変化するエフェクト、エフェクトの減衰、各帯域の位相を回した角度、テイクのピッチ変調を解析します。 |
| `balance` / `balance-bands` / `arrival` | パラメータがチャンネル間のレベル差に与えた影響、帯域ごとの分離に与えた影響、テイクの早い区間と遅い区間がそれぞれ何を含むかを測定します。 |
| `plan` / `block` / `efx-params` | ブロックを問う値を決め、保存済みの記録をアドレスごと・エフェクトパラメータごとの判定 1 つに集約します。 |
| `efx-rate` / `efx-bands` / `efx-time` | 保存済みのテイクから、インサーションエフェクトのスロット 1 つを設定値ごとに読みます。何 Hz で変調したか、1/3 オクターブ各帯域のレベルに何をしたか、返すコピーをどこに置いたかです。 |
| `efx-motion` / `efx-sort` | エフェクトが時間とともに何をするかを追い、静止する型としない型に仕分けます。 |
| `index` / `complete` | 個体の記録を一覧し、完成の基準に対する到達度を数えます。 |
| `document` | 公表された文書の表を 1 ページずつ `documents/` に読み込みます — `init`、`show`、`add`、`status`。 |
| `inferences` | 測定から読み取ったものを問い合わせます — `open`、`closed`、`stale`、`index`。 |

実機ではなく保存済みの記録・文書・推論を読むコマンド — `watch-set`、`motion`、`decay`、`phase`、`verdict`、`balance`、`balance-bands`、`arrival`、`vibrato`、`plan`、`block`、`efx-rate`、`efx-bands`、`efx-time`、`efx-params`、`efx-motion`、`efx-sort`、`complete`、`index`、`document`、`inferences` — は実機を必要としないので、別の測定が機材を占有している間も実行できます。

## データ形式

個体ディレクトリは、測定段階ごとに 1 つのサブディレクトリを持ちます。名前は、その中の記録を書いたコマンドです。記録は、何についてのものか — その実行が問うたアドレス、ブロック、エフェクト型、コントローラ — で名付けられ、アドレス空間の一部ではなく全体を覆う実行は `whole-map.json` です。

```text
data/units/<manufacturer>-<model>-<n>/
  meta.json                 個体の識別情報と測定経路
  measurements.json         記録した観測事項とスポットチェック
  index.json                以下すべての生成された一覧

  sweep/                    読み出せるアドレス領域
  boundary/                 領域が地図どおりの位置で終わるかどうか
  offsets/                  1 バイト読みでしか届かないアドレス
  watch-set/                後段が監視するアドレス。その個体自身の
                            sweep と offsets の記録から組み立てたもの
  write-probe/              受け付けた書き込みと読み戻し結果
  hold-probe/               隣接アドレスが自分の値を保持するかどうか
  window-probe/             他のアドレスの値を映しているアドレス
  power-on/                 電源投入直後に取得した状態
  reset-probe/              リセットで変化する状態
  tone-map/                 利用可能な音色
  efx-map/                  利用可能なインサーションエフェクト
  alias-scan/               メッセージとアドレスの対応
  port-send/  port-read/    応答を返さない MIDI 入力が機体に残したもの

  repeat/                   機体がテイクをどれだけ再現するか。以下の音響比較
                            はすべてこれを基準に読む
  contrast/                 単一アドレスまたはコントローラでの音響比較
  block/                    その比較をアドレスごとの判定 1 つに集約したもの
  efx-params/               インサーションエフェクト 1 型のパラメータ
  balance/                  パラメータがチャンネル間のレベル差に与えた影響
  balance-bands/            同じく、帯域ごとの分離に与えた影響
  arrival/                  直接音が届く区間に置いたものと、エフェクトの
                            戻りが届く区間に置いたもの
  transfer/                 掃引正弦波に対して経路が行ったこと
  motion/  decay/  phase/   エフェクトの変調、減衰、各帯域の位相を
  vibrato/                  回した角度、テイクのピッチ
  efx-rate/                 レートのスロットが設定値ごとに変調した周波数
  efx-bands/                スロットが設定値ごとに 1/3 オクターブ各帯域へ
                            与えた影響
  efx-time/                 ディレイのスロットが返すコピーを置いた位置
  efx-motion/  efx-sort/    静止するエフェクト型としない型
```

`soundings index <個体ディレクトリ>` が `index.json` を再生成します。この一覧は、各記録を、それを書いた段階と、記録自身が述べる対象とともに挙げます。

結果ファイルには、各測定の手法、設定、限界を保存します。仕様書や特許に基づく仮説は、測定結果ではなく測定の背景として記録します。

公表された文書から読み取ったものは、文書ごとに 1 ディレクトリの独立した木に置き、個体の記録には決して混ぜません。

```text
documents/<manufacturer>-<model>-<document>-<language>/
  document.json             文書、読んだファイルの SHA-256、
                            どのページを読んだか
  address-map.json          パラメータアドレスマップの各行
  block-map.json            どのブロックがどのアドレスから始まるか
  by-hand.json              パーサが確信をもって切れず拒否した行を、
                            手で読み込んだもの
  qualifications.json       1 つのアドレスに付いた注記。そのセルが
                            ページの記載のすべてではないことを述べる
  statements.json           表の下に印刷された注記、それが及ぶと読んだ
                            行の範囲、そして未解決として残るもの
```

写し取るのは表だけです。その周りに印刷された散文は、このプロジェクト自身の言葉で言い直すか、言い直していないものとして名前を挙げます。文書そのものはコミットしません。

この 2 つの木から読み取ったものは、独自のスキーマと索引を持つ 3 つ目の木に置きます。散文を読まなくても、測定そのものとそこからの読み取りを区別できるようにするためです。

```text
inferences/
  not-chased.json           モデルに説明を求めていないものと、それぞれ
                            何の測定で範囲を押さえたか
  candidates/<class>.json   パラメータのクラス、当時の技術水準がそこから
                            導くもの、そのバイトの読み取り候補すべて
  models/<name>.json        候補 1 つを、レンダラが読む形式で表したもの
  schema/inference.json     主張が満たすべき形
  <unit>/index.json         主張 1 つにつき 1 エントリ。根拠にした記録つき
  <unit>/<claim>.json       主張、その根拠、実行前に立てた予測、まだ残って
                            いる対抗案、そしてこの主張が閉じないもの
```

## 再現性

`meta.json` には、MIDI・オーディオインターフェース、配線、キャプチャ方法、レベル、関連する機器設定を記録します。データを追加する場合も、他者が測定を再現したり個体差を評価したりできる情報を記録してください。

**ハードウェア MIDI 音源が実際に何を答えるかを、実機から測って記録します。**

take soundings とは、海図の無い海に錘を下ろして深さを測ることです。このプロジェクトは同じことをハードウェア音源の制御面に対して行います — アドレスに書き、読み戻し、返ってきたものを記録する。成果は GM / GM2 / GS / XG にまたがる実測の振る舞いの機械可読なアーカイブです。値域、クランプ、電源投入時の既定値、どのパラメータがどれの別名か、そしてエフェクトの背後にあるアルゴリズム。

## なぜ

仕様は紙の上に存在します。しかし**ある機械が実際に何をするか**は別の問いで、再生を実装するときに効くのはそちらです。マニュアルに載っているアドレスが書き込み専用かもしれず、範囲が書かれている値が別のところでクランプするかもしれず、3 通りの経路で届くパラメータが同じ場所に着くとは限らない。そのどれも、機械可読な形ではどこにも書かれていません。

当時のファイルを再生するソフトウェアの出来が悪いのは、多くの場合サンプルが違うからではなく、**制御面が解釈されていないから**です。このアーカイブは、実装が推測をやめるための参照になります。

## 何があり、何を主張するか

**公開されるすべての行は、機械が返した値です。** マニュアルからの転記はなく、他者のファームウェア解析からの導出もありません。仮説が公刊された文献や特許から来た場合はそれを引用し、それ以外から来た場合は「何を測るか」を決めるためだけに使い、答えを埋めるためには決して使いません。

**主張の単位は製品ではなく個体です。** ある型番のある個体の、あるファームウェアでの測定は 1 つのデータ点であり、アーカイブはそう書きます。別の個体が違う答えを返したなら、それは矛盾ではなく 2 つ目のデータ点で、両方を残します。

```
data/
  units/<メーカー>-<型番>-<n>/
    meta.json          個体の同定・ファームウェア・測定系
    measurements.json  何を答えたか
tools/                 （まだ空。ハーネスは Python パッケージ側）
src/soundings/         測定ハーネス
docs/                  データの読み方と、再現の手順
```

## 動作環境

- Python 3.11 以上と [rye](https://rye.astral.sh/)
- **双方向の** MIDI インターフェース — ここでの測定はすべて往復です
- 実機と、エフェクト測定用のオーディオインターフェース

```sh
rye sync
rye run soundings devices
```

## 何かを信じる前に selftest を通す

この測定が壊れる道は 2 つあり、**どちらも黙って壊れます。**

バイトを落とす MIDI 経路は、エラーではなく**行の欠落**を生みます。アドレス空間に穴が空き、それが「存在しない」と読めてしまう。サンプルを落とす録音経路は、**レベルはすべて正しく、時間軸だけが縮んだ**録音を生みます。すべての減衰時間が同じ比率で短くなり、データの内部では何一つ矛盾しません。

どちらも測定結果からは後から検出できません。**答えが既に分かっている刺激に対して、先に排除する**しかない。

```sh
rye run soundings selftest --audio "<お使いのインターフェース>"
```

返信のチェックサムを検証し、同じアドレスを 100 回読んで全部一致することを要求し、1 秒間隔でノートを鳴らして録音側も 1 秒間隔だと言うことを要求します。

```sh
rye run soundings identity
rye run soundings read "40 01 30" 16
```

## 測定の再現

個体ごとの `meta.json` が測定系の全体を記録します — 配線、レベル、つまみの位置、録音方法。**再現できない測定は逸話**だからです。選択の余地があるところは再現性で選びます。ボリュームは突き当たりの位置で記録しますが、それが**目盛りの無いつまみで他人が厳密に一致させられる唯一の位置**だからです。
